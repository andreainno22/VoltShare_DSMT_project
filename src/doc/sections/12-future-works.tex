\section{Future Works}
\label{sec:future}

Four extensions, none started, each with the reason it was set aside.

\paragraph{Site power shared across stations.} Two stations on the same grid connection
would share one budget, a divisible quantity to be lent and returned between nodes: a lease
over a continuous value, where the leases of this document are over exclusive resources. It
was left out because it would have added a second network-wide invariant before the first
one was demonstrably safe under failover.

\paragraph{Partitioning the vehicle space across coordinators.} Each claim would be
decided by the node responsible for a hash of the vehicle identifier, so no node would see
all the traffic and a failure would block one shard. \Cref{sec:p2} gives the reasons it was
set aside; it builds on the current design and would keep its election and quorum.

\paragraph{The waiting list.} Specified in \cref{sec:functional} and absent from the
delivered system. It needs a per-station queue with an owner and an offer that is itself a
lease, so that an absent waiter cannot freeze the queue; the protocol side already names
the action and the notification kind.

\paragraph{Native push notifications, and an operator console.} There is no mobile push,
so the overstay notice reaches a driver who is looking at the page or who reopens the
application later, and the grace period assumes an attentive driver. The back office is
read-only: taking a connector out of service by hand would be a command from the web tier
into the cluster, a direction the JInterface bridge already carries for suspensions.
