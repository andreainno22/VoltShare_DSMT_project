\section{API and Protocol Specification}
\label{sec:api}

Five channels carry everything in this system, and \cref{sec:protocols} said which runs where
and why. This section specifies what travels on each one.

The three channels between our own components were written as contracts before either side
was implemented, and they live in the repository as \texttt{contracts/*.md}. Two of them are
marked \emph{frozen}: changing one requires a review by both developers, because each side is
written by a different person against the text and not against the other's code.

\subsection{HTTP: browser to back office}
\label{sec:api-http}

Nine servlets, mapped with \texttt{@WebServlet} annotations and no deployment descriptor.
Everything is rendered server-side and forwarded to a JSP; there is no JSON API on this
channel, because the browser receives pages.

\subsubsection{The token the station will trust}
\label{sec:api-jwt}

A station has to recognise a driver without asking the back office. That is what keeps a
site working while Tomcat is down, and what keeps driver traffic off the Java container. The
token is the only thing the two sides share.

It is a JWT signed with \textbf{HS256} using a symmetric secret, passed to both sides in the
environment as \texttt{VOLTSHARE\_JWT\_SECRET} and at least 32 characters long, because
HS256 needs 256 bits of key material and the Java library refuses to sign with less. It
lives 60 minutes. Java signs with \texttt{jjwt}, Erlang verifies with \texttt{jose}.

\begin{lstlisting}[language=json, caption={The claims, plus the standard \texttt{iat}.},
                   label={lst:jwt}]
{ "sub": "12", "username": "andrea", "vehicle_id": 88,
  "iss": "voltshare-backoffice", "exp": 1755792000 }
\end{lstlisting}

\texttt{sub} is the user id as a string, which the JWT specification requires, and
\texttt{vehicle\_id} is a number. The station needs both: the first attributes the session
to an account, the second matches the claim, which is per vehicle.

On the first frame of the WebSocket, which must arrive within five seconds of the connection
opening, the station verifies the signature, checks that \texttt{iss} is exactly
\texttt{voltshare-backoffice}, checks that \texttt{exp} is in the future, and extracts the
two identifiers. A failure closes the socket with \texttt{4401}, an expired token with
\texttt{4408}. The station never calls the back office about a token, whether it accepts one
or throws it out.

There is a trap here that the library invites, and \texttt{contracts/sample-tokens.md}
records it: \texttt{jose\_jwt:verify/2} checks \emph{only the signature}. Issuer and expiry
are ordinary claims, so a token that verifies is not yet a token to accept, and both checks
are written out explicitly on the station side.

\paragraph{How the token reaches the browser.} It never passes through JavaScript storage.
The servlet puts it in the session, the JSP renders it into a hidden element as a
\texttt{data-} attribute through \texttt{<c:out>}, and the WebSocket code reads it from
there.

The shape matters for a reason that is not obvious. An earlier version declared these values
as JavaScript constants inside a \texttt{<script>} block, which meant the JSP was building
JavaScript source out of EL. Only the token is the back office's own: the WebSocket URL
comes from a station node, travels in its \texttt{station\_up} announcement through the
coordinator, and is republished by \texttt{StationDirectory}. A station announcing itself
with a URL containing a quote and a semicolon would have closed the string and run its own
script on every driver's page. An attribute rendered through \texttt{<c:out>} cannot become
code, whatever it contains, because it never reaches a JavaScript parser.

\subsection{WebSocket: driver to station}
\label{sec:api-ws-driver}

The page opens \texttt{ws://<station>:8080/ws/driver?station\_id=<id>}. Host and port are
what the station announced about itself, republished by \texttt{StationDirectory}
(\cref{sec:api-bridge}); the query string is appended by \texttt{js/ws.js} from the station
the page believes it is showing, and \texttt{vs\_driver\_ws} closes with \texttt{4400} on a
mismatch. Frames are text, one JSON object each, with one envelope in both directions: an
\texttt{action} going in (a \texttt{type} coming back), a \texttt{request\_id}, and a
\texttt{payload} that is \texttt{\{\}} when there is nothing to say. Every decision is taken
in \texttt{vs\_driver\_proto}, a module of pure functions over a session map, so the whole
contract runs under EUnit without a listener; \texttt{vs\_driver\_ws} holds the Cowboy
callbacks and nothing else.

\paragraph{Handshake.} The first frame has to be \texttt{join}, carrying the JWT of
\cref{sec:api-jwt}, and it has to arrive within 5~s (\texttt{JOIN\_TIMEOUT\_MS}). The
station verifies it locally
and binds \texttt{user\_id} and \texttt{vehicle\_id} to the connection; the reply is an
\texttt{ack} with a first \texttt{state} behind it in the same write. Four close codes:
\texttt{4400} for a binary frame, malformed JSON or a wrong \texttt{station\_id};
\texttt{4401} for a bad token, an action before \texttt{join}, or no \texttt{join} in time;
\texttt{4408} for an expired token, so the page can tell ``log in again'' from ``something
is wrong''; \texttt{1001} when the station shuts down, which the page answers by
reconnecting with backoff.

A connector's \texttt{state} is one of \texttt{free}, \texttt{held}, \texttt{charging},
\texttt{suspended}, \texttt{complete}, \texttt{overstay}, \texttt{closing} and
\texttt{out\_of\_service}, the last being the wire name for a connector with no process
answering for it. The periodic tick earns its place beside the event-driven pushes: meter
readings change \texttt{power\_kw} without raising a connector event, and an event-only
channel would show a live session at a frozen power. A WebSocket \texttt{ping} rides on the
same tick, so that Cowboy's inbound-only idle timeout (60~s) does not hang up on a page
that is only watching. The \texttt{session} phase is read
off the connector's own state, since zero kilowatts is ambiguous between a starved
allocation and a deep taper; \texttt{overstay\_seconds} is the net figure, grace already
subtracted, the same number that ends up in \texttt{sessions.overstay\_seconds}. A session
ends by disappearing from the snapshot, and \texttt{session\_push/3} turns that
disappearance into a final frame with the phase \texttt{closed}.

\begin{sloppypar}
The station produces six notification kinds, \texttt{reservation\_expiring},
\texttt{reservation\_expired}, \texttt{claim\_revoked}, \texttt{charge\_complete},
\texttt{overstay\_started} and \texttt{session\_interrupted}; a seventh,
\texttt{waitlist\_offer}, is specified and has no code path that can raise it. The manager
broadcasts each event to every subscribed socket, and the socket delivers it only when the
user it names is the user the token bound. One table, \texttt{notification\_text/1},
supplies the sentence for this frame and for the durable copy that reaches
\texttt{notifications.jsp}.
\end{sloppypar}

\paragraph{Decisions on this channel.}
\begin{itemize}
  \item \textbf{Identity comes from the token alone.} \texttt{held\_by\_me}
        and \texttt{mine} are computed on the station, and a notification is delivered only
        when the user it names is the one the token bound, a filter written as a pattern in
        the clause head of \texttt{websocket\_info/2}. The alternative, a \texttt{user\_id}
        field in the request, would let a driver reserve or cancel on behalf of somebody
        else by editing a frame.
  \item \textbf{One \texttt{RETRY\_LATER}, the cause in the message.} Three facts share the
        code (the coordinator is rebuilding, the station is starting, the connector process
        is between a crash and its restart) because the client must do the same thing in all
        three. Three codes would put a piece of the station's internals into every client.
        The third case used to be answered \texttt{UNKNOWN\_CONNECTOR}, a permanent code for
        a condition that lasts milliseconds.
  \item \textbf{The \texttt{session} frame rides on the \texttt{state} tick.} A timer of
        its own was rejected: two frames from two instants would show a power read at one
        moment next to an energy read at another.
  \item \textbf{The socket is stateless; the reservation is not.} Reconnection is the
        client's job (backoff from 500~ms, capped at 10~s, fresh \texttt{join}), and the
        station keeps nothing for a disconnected socket, because the reservation lives in
        the connector process and survives the browser being closed.
\end{itemize}

\subsection{WebSocket: charge point to station}
\label{sec:api-ws-cp}

This channel is the boundary of the system: above it is production logic, below it is
emulated hardware, and the emulator is credible only if a real charge point could
implement the interface. The message set is a reduced OCPP 1.6-J, with the same direction
of authority and a fraction of the surface; \cref{tab:cp-messages} maps every message to
its original. The charge point is the client and dials
\texttt{ws://<station>:8081/ws/cp?\allowbreak station\_id=<id>\&connector\_id=<n>}, as
real equipment dials an operator's backend from behind the NAT of a site network. The
envelope is the one of \cref{sec:api-ws-driver}, so one codec serves both channels, but
\texttt{request\_id} is only a correlation key for the logs: nothing on this channel is
retried and there are no \texttt{error} frames, so a frame the station cannot read is
logged and dropped. There is no authentication: the link is site-local, and in a
deployment it would be mutual TLS, which we did not implement.

\paragraph{Admission and boot.} \texttt{vs\_cp\_proto:handshake/2} closes with
\texttt{4404} only for a permanent condition: the connector is not one of this station's,
or the query names another station. A connector that is configured here but has no
process behind it at that instant, because the node is starting or the supervisor is
restarting the process, is admitted, and the answer comes at the \texttt{boot} as
\texttt{accepted: false} with the reason \texttt{connector not ready}; the equipment
retries on its own backoff (1~s, doubling, capped at 30~s in \texttt{cp.js}); a second
socket for the same connector replaces the first, closed with \texttt{4409}. The
\texttt{boot} ack carries everything the equipment needs in order to behave, so it carries
no configuration of its own: \texttt{heartbeat\_interval\_s} (30),
\texttt{meter\_interval\_s} (5), \texttt{server\_time}, and the \texttt{limit\_kw} in force.

\paragraph{Silence.} A heartbeat every 30~s and a meter reading every 5~s while charging:
the contract obliges the equipment to speak, so Cowboy's inbound-only idle timeout
\emph{is} the missed-heartbeat rule, and this channel needs no \texttt{ping}. The budget is
three intervals, 90~s, split as \cref{sec:cp-failure} describes.

\paragraph{Authorisation happens at \texttt{plugged}, and nowhere else.} The payload names
a vehicle, and the station resolves it to an account locally through
\texttt{vs\_station\_db:user\_for\_vehicle/1}, because the mapping is one to one in the
schema and the coordinator does not own that table. This is the limit measured in
\cref{sec:station-failures}: an isolated station finishes what it started and cannot start
anything new, since the lookup has to cross the cut. \texttt{max\_kw} is mandatory and a
\texttt{plugged} without it opens no session; the alternative was a ceiling of zero, a
demand of zero from the allocator of \cref{sec:p5}, and a car sitting at zero kilowatts
for ever with nothing in any log to say why.

\paragraph{Meter and commands.} \texttt{energy\_kwh} is cumulative since the session
started, and the connector stores \texttt{max(stored, reported)} so that a counter which
resets on a firmware glitch cannot subtract energy already billed. A \texttt{meter} for a
connector with no session is dropped and logged. \texttt{unplugged} carries the final
total; at that point the station writes the \texttt{sessions} row with energy and
overstay, releases the claim and moves the connector to \texttt{free}.
\texttt{set\_limit} is the allocator's output (\cref{fig:seq-cp}); \texttt{limit\_kw: 0}
means suspended. \texttt{stop} carries one of six reasons (\texttt{driver\_stopped},
\texttt{target\_reached}, \texttt{claim\_revoked}, \texttt{not\_your\_reservation},
\texttt{faulted}, \texttt{station\_shutdown}), the last sent by \texttt{vs\_cp\_ws} just
before the \texttt{1001} close, because after the listener is gone there is nobody left to
tell. A \texttt{stop} ends the delivery and the connector stays occupied until
\texttt{unplugged}; \texttt{faulted} is the exception, closed at once with the energy last
measured, because faulted equipment may never send another frame.

\paragraph{Reconciliation after a station restart.} The connector processes die with the
node and the station has no memory of the session. The charge point reconnects, boots,
and re-sends \texttt{plugged} with two optional fields, \texttt{energy\_kwh} and
\texttt{charging\_seconds}; the station adopts what the hardware reports and opens a
session from those figures instead of stopping a car that is charging happily, with
\texttt{started\_at} set to \emph{now} minus \texttt{charging\_seconds} on the station's
own clock. Before the field existed, a session that crossed two restarts was billed the
right energy over the wrong window: on 28 August, row 18 of \texttt{sessions} carried
12.042~kWh and a duration of twenty-three seconds. Measured on 3 September with
\texttt{docker kill station2}: 34.795~kWh on the connector before the kill, 34.812 after
the restart, and no row written for the session that was lost. The reservation is not
reconstructed, because re-deriving it would mean trusting hardware on a question hardware
cannot answer. The mirror case is
the connector process dying under a healthy socket; the socket monitors the connector,
retries the attachment every 500~ms five times, replaying the last \texttt{status} and
\texttt{plugged} it saw, and past the budget closes with \texttt{1012}, Service Restart.

\paragraph{Decisions on this channel.}
\begin{itemize}
  \item \textbf{A subset of OCPP 1.6-J, with the same direction of authority.} Full OCPP
        was rejected for its surface: configuration keys, id tags, a nine-state model,
        charging profiles with stacking levels, none of which the coordination problem
        needs. An invented protocol was rejected too, because it would have left the
        emulator with nothing to be an emulator of. \Cref{tab:cp-messages} is the
        reduction, message by message.
  \item \textbf{One socket per connector.} OCPP multiplexes every outlet of a unit over one
        socket with a \texttt{connectorId} field. Here the socket \emph{is} the connector,
        which costs a few file descriptors and gives a direct mapping from socket to owning
        process, the shape the actor model of \cref{sec:p1} wants.
  \item \textbf{Limits are repeated on every tick.} \texttt{set\_limit} goes out on every
        arrival, departure and tick, even when unchanged, so a missed frame is corrected
        within one tick. Delta tracking was rejected on a channel with no ordering problem
        to justify it.
  \item \textbf{Timestamps that matter are the station's.} The equipment sends quantities
        it measured itself, cumulative energy and a duration, never an instant. A
        \texttt{started\_at} from the hardware was rejected because two clocks minutes
        apart would have produced two different sessions from one cable.
  \item \textbf{\texttt{4404} only for a permanent condition, \texttt{1012} for a
        temporary one.} The first version answered \texttt{4404} in both cases, and
        \texttt{4404} is the code the emulator dies on. A charge point that knows nothing
        of how the station repairs itself does the right thing by reading the code alone.
\end{itemize}

\subsection{Claims: station to coordinator}
\label{sec:api-claim}

Distributed Erlang, with the coordinator a \texttt{gen\_server} registered locally as
\texttt{vs\_coord\_srv} on each coordinator node and addressed as
\texttt{\{vs\_coord\_srv, Node\}}. Calls carry a 2000~ms timeout, and a timeout is treated
exactly like an unreachable node.

\subsubsection{Acquire}

\begin{lstlisting}[language=Erlang, caption={Request and the four possible replies.},
                   label={lst:claim}]
{claim, ReqId, VehicleId, UserId, StationId, ConnId}

{ok, ReqId, ClaimId, GrantedAt, ExpiresAt}
{error, ReqId, already_held | suspended | rebuilding | unknown_station}
{not_serving, LeaderNode | undefined}
\end{lstlisting}

Each refusal means something different to the driver, so the station maps them apart:
\texttt{already\_held} says this car is committed at another station,
\texttt{suspended} says the account is serving a no-show penalty, and
\texttt{rebuilding} is temporary and produces a retry rather than an error on screen.
\texttt{unknown\_station} means the coordinator has not heard the announcement yet, so the
station re-announces itself and tries once more.

Two properties of the reply are load-bearing elsewhere in this document.
\texttt{ExpiresAt} is always longer than the reservation lease, by
\texttt{CLAIM\_GRACE\_SECONDS}, so a claim never expires underneath a reservation that is
still alive. And \texttt{GrantedAt} is issued by the coordinator, never by the station, for
the reason given in \cref{sec:p2}: the station stores it and echoes it back, so that
\emph{oldest wins} always compares two timestamps that came from the same clock.

\subsubsection{Renew, and why it carries more than it seems}

A station renews all its claims in one message every ten seconds, and the reply names those
still valid and those revoked.

\begin{lstlisting}[language=Erlang]
{renew, StationId, [{ClaimId, VehicleId, ConnId, UserId, GrantedAt}]}
{renewed, Ok, Revoked, NewExpiresAt}
\end{lstlisting}

Every renewal carries \texttt{GrantedAt} and \texttt{UserId}, including the hundredth one
for a claim nothing has disturbed. The reason is recovery: a renewal is how a newly elected
leader learns about claims it never granted. A claim it has never seen is \textbf{accepted} and adopted with the timestamp
the station reports, which is what makes \cref{sec:rebuild} converge even when the rebuild
query reaches nobody. Carrying \texttt{UserId} lets that leader enforce a suspension
immediately, instead of holding a claim it cannot attribute to an account.

A revoked claim is not an error to be logged. The station must cancel the reservation or
stop the session, free the connector, and tell the driver why. Revocation is how the system
converges after a conflict, and the station obeys it even when it believes its claim is
valid.

\subsubsection{Finding the leader}

The station keeps its idea of the current leader in \texttt{vs\_claim\_client}, starting
from the first entry of \texttt{COORD\_NODES}. A \texttt{not\_serving} carrying a node
updates it and the call is retried once. A \texttt{not\_serving} without one, a timeout or a
\texttt{noproc} makes it walk the configured list round-robin, for at most one full pass.

If the pass fails, the station gives up and refuses the reservation. It does not queue the
request and it never blocks the connector process, which is the rule that keeps a
coordination outage from touching cars that are already charging: no claim means no new
reservation, and walk-in charging on a free connector needs no claim at all.

\subsubsection{Behavioural rules}

Binding on both implementations, and each one is a guarantee something else in this document
depends on:

\begin{enumerate}[itemsep=1pt]
  \item \textbf{Claim first, commit after.} A connector never moves to \texttt{held} before
        the \texttt{ok} arrives.
  \item \textbf{No claim, no reservation.} An unreachable coordinator means refusals.
  \item \textbf{The coordinator serves only as leader and in quorum.} In any other state it
        answers \texttt{not\_serving} or \texttt{rebuilding}, never a grant.
  \item \textbf{Revocation is authoritative.}
  \item \textbf{Oldest wins}, by \texttt{GrantedAt}.
  \item \textbf{Releases are best-effort.} Correctness never depends on one arriving, because
        expiry is the backstop.
\end{enumerate}

\subsection{The JInterface bridge: coordinator to back office}
\label{sec:api-bridge}

The back office does not poll the cluster. It joins it. Java opens an \texttt{OtpNode} named
\texttt{voltshare\_bo}, registers a mailbox called \texttt{backoffice}, and receives Erlang
terms as the coordinator produces them. Every page that lists stations then reads from
memory.

Java is a \textbf{hidden node}: it takes part in the distribution protocol and is addressable
by name, but it does not appear in \texttt{nodes()} and takes no part in the quorum. That is
the correct arrangement, because the back office must never influence who is elected leader.
The bridge runs on its own daemon thread and reconnects every three seconds, so a
coordinator restart never requires restarting Tomcat.

\paragraph{A detail that cost a day.} The \texttt{jinterface} artifact published on Maven
Central is version 1.6.1, from 2011, and it cannot complete the distribution handshake with
an OTP 29 node: \texttt{OtpNode.ping} returns false with no exception to point at the cause.
The jar we ship is built from the sources of the OTP release we run, and it has to move
whenever the OTP version in \texttt{Dockerfile.erlang} moves.

\texttt{stations\_update} is always a complete snapshot. \texttt{StationDirectory} replaces
its whole list atomically, because a partial update would leave a station on the page after
its node had gone down. The WebSocket URL inside it is produced by the coordinator and never
assembled by Java: the back office does not know the deployment topology, and publishing a
reachable address is the cluster's job. A malformed entry is logged and skipped, so one
broken station cannot blank the directory.

\paragraph{Suspensions recover by pushing.} The suspended set lives in the coordinator's
memory while the counter behind it lives in MySQL, so a coordinator that has just started
serving knows nothing about it. It cannot ask the stations either, because no station holds
a suspension. The back office therefore repeats every running suspension on each
\texttt{leader} announcement it hears, and the serving coordinator republishes that
announcement every 30 seconds. A coordinator that restarts and wins again converges without
anyone asking a question.

This is the asymmetry worth noticing, and \cref{sec:station-failures} states it in one line:
claims are recovered by \emph{asking}, because the stations own them, and suspensions by
\emph{pushing}, because nobody in the cluster does. State is recovered from whoever owns it,
in whichever direction that turns out to be.

\paragraph{What happens when the bridge fails.} No coordinator reachable at start-up means
retries every three seconds, and pages that show an empty list with a warning: a stale list
presented as current would be worse than none. A coordinator dying while Tomcat runs leaves
the last snapshot in memory, marked stale after 90 seconds. Tomcat dying leaves the cluster
untouched, because the back office sits on the path of no reservation and no session.
